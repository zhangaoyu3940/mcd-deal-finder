# 失败兜底策略

**核心原则：宁可少说，不可瞎说。** 任何兜底都必须明确告知用户"拿不到实时数据"，绝不编造价格、优惠券、活动。

---

## 1. 失败分类与响应矩阵

| 代码 | 场景 | 检测方式 | 响应策略 |
|---|---|---|---|
| **F1** | 无 MCP 通道 | `probe()` 返回 `store_locate=None` 且 `menu_browse=None` | 明确告知未接入，提供接入指引；**不推荐任何套餐** |
| **F2** | 门店定位失败 | 定位返回空列表 | 反问城市/地址；提供"手动选门店"入口；**不猜价格** |
| **F3** | 菜单拉取失败 | menu 返回空或异常 | 说明失败原因，给出重试按钮；**禁止沿用上次缓存价格** |
| **F4** | 无可用优惠券 | coupon 列表为空 / 全部 claimed/过期 | 切「无券模式」：按原价推荐，标注"当前无可用券" |
| **F5** | 优惠券已领完 | `remain == 0` | 排除该券；若全部领完转 F4；**不推荐已领完的券** |
| **F6** | 活动已结束 | `expires_at < now` | 剔除该活动；提示"X 活动已于 Y 结束"；**不推荐过期活动** |
| **F7** | 领取失败 | claim 返回 error | 原样转述错误码；**不重试超过 1 次**；告知用户去官方 App 手动领 |
| **F8** | 叠加被拒 | 试算返回「券不可叠加」 | 降级为单张最优券，告知用户已改为单券 |
| **F9** | 预算无法满足 | 所有方案 > budget | 诚实告知最低可行价，给出 2 个选择：提预算 / 减人数换口味 |
| **F10** | 时间冲突 | 券时段与用餐时段不重叠 | 剔除该券并说明原因；**不推荐用不上的券** |
| **F11** | 字段缺失 | 关键字段为 None | 该项显示"未获取到"，**该方案标注"数据不完整，仅供参考"** |
| **F12** | 券无金额信息 | `has_amount_info=False`（券名解析不出金额） | **排除该券**，说明"该券需领取后到门店查询具体金额"；不得估算 |
| **F13** | 随单购未同步 | 推荐了 `canWithOrder=true` 的商品 | 必须提示"下单时需同步选择随单购卡，否则按原价购买" |

## 1.1 mcd-mcp 特有兜底

| 场景 | 现象 | 处理 |
|---|---|---|
| 未传 `beType`/`orderType` | 接口报参数错误 | 必须补齐；`beType=1` 时不能传 `beCode` |
| 外送但无 `addressId` | `delivery-query-stores` 报错 | 先调 `delivery-query-addresses` 取地址 ID |
| 券无面额 | `query-store-coupons` 不返回金额 | 走 `parse_amount_from_title()`；解析不出转 F12 |
| 试算与估算不符 | `calculate-price` 与本地计算差值 | **以服务端为准**，并说明差额来源（运费/餐具费/额外促销） |
| `enjoyable.balance > 0` | 有券因未达门槛未生效 | 提示"再加 ¥X 可用券"，净收益为正才建议凑单 |

## 2. 各场景用户话术模板

### F1 — 无 MCP 通道
> ⚠️ 当前环境未接入麦当劳 MCP，我拿不到实时菜单价格和优惠券，**不会给你编造一个假的省钱方案**。
>
> 接入方式（任选其一）：
> 1. 在连接器管理中搜索「麦当劳」并绑定；
> 2. 若你有自建 MCP，把配置加到 `~/.workbuddy/mcp.json` 后在自定义连接器入口点「信任」；
> 3. 告诉我 MCP 端点地址，我帮你写好配置。
>
> 接入后重新说一遍需求即可，例如："3 个人，80 以内，不要辣"。

> 🔍 没找到符合条件的麦当劳门店。帮我补充一下：
> - 你在哪个城市/商圈？（或者直接给我一个地址）
> - 要堂食、外送还是自助点餐？
>
> 定位到门店后我再拉该店菜单和可用券，价格以下单时为准。

## 3. 降级链（从优到劣）

```
最优：门店 + 菜单 + 可用券 + 套餐详情 → 精确最优解
 ↓ coupon_claim 不可用
次优：门店 + 菜单 + 可用券（不领券，只告知可领）→ 精确最优解（券显示为"待领取"）
 ↓ combo_inspect 不可用
降级：门店 + 菜单（单品价）→ 按单品拼组合最优解
 ↓ promo_activity 不可用
简化：只算已持有券（coupon_owned），不提示可领券
 ↓ coupon 能力全失
无券模式：按原价推荐，标注"无券可叠加"
 ↓ menu_browse 不可用
停摆：仅告知失败（F3），不给方案
 ↓ store_locate 不可用
停摆：仅告知失败（F1/F2），不给方案
```

**每一级降级都必须在输出中显式声明当前处于哪一级**，不能静默降级。

## 4. 硬性禁止项

| 禁止 | 原因 |
|---|---|
| 编造价格 | 用户会拿去买单，差额由用户承担 |
| 编造优惠券（券名/面额/有效期） | 同上，且可能误导决策 |
| 沿用缓存价格冒充实时价格 | 麦当劳价格与活动是动态的，缓存必然过期 |
| 静默降级 | 用户以为是最优解，实际是次优解 |
| 自动领券不询问 | 写操作，且可能占用用户权益/触发风控 |
| 代用户下单 | 超出 Skill 定位，涉及金钱交易 |
| 在券过期后仍推荐 | 无效推荐，浪费用户时间 |
