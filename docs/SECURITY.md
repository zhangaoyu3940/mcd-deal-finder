## 报告漏洞

**请勿通过公开 Issue 报告安全漏洞。**

请通过 GitHub 仓库的 **Security → Report a vulnerability** 私下报告，
或联系作者（见 [COMPETITION.md](COMPETITION.md)）。

报告时请说明：
- 漏洞类型与影响范围
- 复现步骤或 PoC
- 受影响的文件与行号

我们承诺在收到报告后 **72 小时内**确认并给出初步处置意见。

## 安全设计说明

本项目在设计时已考虑以下安全边界：

### 1. 不执行下单等金钱交易操作

本项目**不调用任何下单接口**（`create-order`、`mall-create-order`、
`party-order-create` 等），仅进行查询、试算与推荐。
「计算方案」与「实际下单」之间始终存在人工确认环节。

### 2. 写操作需明确授权

`auto-bind-coupons`（一键领全部优惠券）是唯一的写操作。
Skill 在调用前**必须**将待领取的券展示给用户并获得明确同意，
不允许静默调用。

### 3. 不编造数据

这是本项目最核心的安全约束。所有价格、优惠券、活动信息
**必须来自 MCP 接口的原始返回**，禁止任何形式的估算或臆造。

具体表现为：

| 场景 | 处理方式 |
|---|---|
| 接口未返回券面额 | 从券名反推；解析不出则**排除计算**，不猜测 |
| `available-coupons` 无金额 | 标记「无金额信息」，仅提示「有券可领」 |
| 字段缺失 | 显示「未获取到」，方案标注「数据不完整」 |
| 试算失败 | 标注未验证，不伪造权威价 |

理由：本项目的输出会直接指导用户下单。若金额是编造的，
差额将由用户承担。

### 4. 最小权限与数据隐私

- 项目**不收集、不存储、不上传**任何用户数据；
- 不含埋点、日志上报、遥测逻辑；
- 用户可通过删除本地目录完全移除项目。

⚠️ 使用提示：MCP 服务在调用时可能需要门店位置、卡包券等数据，
这些数据仅在用户环境与 MCP 服务间传输。**请勿在调试日志中打印
MCP 返回的完整内容**，以免泄露个人数据。

### 5. 输入解析安全

MCP 返回的内容被当作**不可信输入**处理：

- 使用 `parse_json_loose()` 做括号配平提取，不使用 `eval`；
- 正则表达式均针对结构化字段，不对用户输入做动态拼接；
- 金额统一转 `int`（分），避免浮点精度问题与数值溢出。

## 依赖安全

本项目**零第三方运行时依赖**，仅使用 Python 标准库。
这消除了第三方依赖引入供应链攻击的风险。

若未来引入依赖，将在此处声明并说明用途。

## 已知限制（诚实声明）

| 限制 | 影响 |
|---|---|
| 依赖外部 MCP 服务 | 数据准确性由 MCP 提供方保证，本项目不承诺 |
| 券名反推依赖命名规范 | 若麦当劳变更券命名规则，反推可能失效（会安全降级为「不参与计算」） |
| 门店价格随时间变化 | 输出仅供参考，以下单时官方渠道为准 |
| 候选池可能较小 | 某些门店去重后可能只有 1 个可行方案 |

以上限制均为**设计上的安全降级**，不会导致错误推荐，
只会导致推荐范围变窄或明确提示信息不足。
